# B2B Gap Analysis

Date: 2026-06-24

- B2B launch session model, dedicated operator-game assignment model, operator-scoped game availability/session guard, provider adapter contract with capability states/catalog listing/validation/normalization, explicit wallet action contract profile, provider-backed session close, and public launcher bridge to the legacy launcher.
- Shadow user foundation.

- Reporting endpoints for summary, transactions, GGR, settlements, deterministic settlement export snapshots/detail, and reconciliation exposure/aging. Settlement export requires a deliberately scoped API key with `reports.export`.
- Signed operator portal endpoint at `/api/b2b/v1/portal`, JSON overview at `/api/b2b/v1/portal/overview`, signed HTML workflow pages for credentials, games, sessions, transactions, settlements, cases, callbacks, diagnostics, reports, support, logs, and docs, signed downloadable OpenAPI/Postman JSON artifacts under `/api/b2b/v1/portal/docs/openapi.json` and `/api/b2b/v1/portal/docs/postman_collection.json`, signed tenant-scoped game drilldown pages under `/api/b2b/v1/portal/games/{game_uid}`, signed tenant-scoped session drilldown pages under `/api/b2b/v1/portal/sessions/{session_uid}`, signed tenant-scoped transaction drilldown pages under `/api/b2b/v1/portal/transactions/{transaction_uid}`, signed tenant-scoped settlement drilldown pages under `/api/b2b/v1/portal/settlements/{settlement_uid}`, signed tenant-scoped provider diagnostic drilldown pages under `/api/b2b/v1/portal/diagnostics/{request_uid}`, signed operator support-case comment/detail/thread-page endpoints under `/api/b2b/v1/portal/support/cases/{transaction_uid}`, and a tenant-scoped support ticket lifecycle under `/api/b2b/v1/portal/support/tickets`. Portal surfaces return tenant-scoped profile, credential, public API-key scope names, game assignment, session, wallet, callback, provider launch diagnostics, support, settlement, recent game/session/transaction/settlement/provider-diagnostic detail endpoint paths, open/recent reconciliation cases with state-aware support-case comment endpoint paths, support-ticket summaries with state-aware comment/close/reopen endpoint paths, support case/ticket JSON detail endpoint paths, support case/ticket HTML thread page paths, and redacted API/audit logs without secrets, URL query strings, or raw payloads; game drilldown pages show catalog summary, assignment, real/demo availability, successful wallet amounts, and related session/transaction links without launch secrets or raw payloads; session drilldown pages show summaries, successful wallet amounts, and related transaction links without launch secrets or raw payloads; transaction drilldown pages show summaries, transitions, callback attempts/logs, reconciliation items, and manual actions without raw request/response bodies; settlement drilldown pages show summary, totals, breakdown, approval trail, and export metadata without export content or raw payload bodies; provider diagnostic pages show provider request status/action/duration plus redacted request/response summaries without launch URLs, launch tokens, raw provider payloads, or foreign rows; support-ticket summaries include message counts and latest redacted operator/staff message context; support-case and support-ticket detail readback returns bounded redacted operator-visible threads; support comments and tickets are redacted before persistence and audited, including operator-side reopen events.

## Missing Or Incomplete

### P0/P1 Before Production

- Staging migration rehearsal tooling is present and release-gated; an actual upgraded production database migration verification run remains required on a staging copy before launch.
- Production environment must pass `b2b:release-check --production`; the current local workspace now passes the Composer audit and production release-check gates on PHP 8.3 / Laravel 12. B2B shared-state defaults now point at Redis, sandbox defaults to disabled, production session cookies are required to be database-backed, secure, HTTP-only, and SameSite protected; production login throttling, password policy, and credential-change session revocation are release-gated; and previously tracked local secret files have been removed from the current tree, but any secrets committed to history still require rotation before launch.
- Production Composer dependency audit is green after removing debug tooling from Composer dependencies, replacing legacy Faker, localizing runtime settings/presenters, localizing API JWT auth, localizing roles/permissions, localizing Form/HTML facades, removing unused/legacy direct dependencies such as `laravel/ui`, `fideloper/proxy`, the SMS.to Laravel wrapper, `laravel/legacy-factories`, server-side Yajra DataTables, `proengsoft/laravel-jsvalidation`, `pragmarx/google2fa-laravel`, `tymon/jwt-auth`, `jeremykenedy/laravel-roles`, `laravelcollective/html`, transitive `eklundkristoffer/seedster`, and transitive `laravel/helpers`, and upgrading the platform to PHP 8.3 / Laravel 12 with Symfony Mailer.
- External provider adapters still require real provider-specific implementations and certification docs against the explicit wallet action contract profile.
- Production-grade wallet state machine still needs external provider certification and provider-certified reversal semantics. The current foundation has explicit transition validation, append-only transition logging, recursive sensitive-field redaction, retryable `unknown`, retry-budget `dead_letter`, operator-scoped status lookup, provider-declared status/rollback contracts, reconciliation item scanning/reporting with conservative operator `transaction_status` resolution, bounded rollback recovery, privileged CLI guard, audited CLI and web manual actions, deterministic settlement exports, audited CLI and web settlement submit/approve/reject actions, and password-verified session-bound web step-up confirmation.

## Conflicts And Duplicates Found

- Duplicate B2B route includes in `routes/api.php` and `routes/web.php`.
- Mismatched route namespace for B2B launcher.
- Mismatched route action for game launch.
- Wallet v7 route prefix duplicated the `/api` segment.
- Reporting migration used `game_id` while schema used `game_uid`.
- B2B docs claimed capabilities that were only partial foundations in code.
